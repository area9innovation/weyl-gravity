\section{Purpose}

This supplement is the destination for verification details removed from the
main narrative: recurrence bounds, interval cells, projective chart changes,
contour panels, mutation tests, content hashes, and exact commands.  The
theorem statements and proofs in the main paper are the mathematical
authority.  The machine-readable certificates provide pinned reproducibility
records, exact witnesses, validation margins, and independent implementation
checks.  A timeout, skipped verification, or reproduced producer output is never
recorded as an independent verification pass.

hierarchy:

Rerunning a producer is reproduction, not verification.  Each manifest
records its independence profile and all shared dependencies.

Every publication record pins
\[
(\text{repository commit},\ \text{certificate SHA-256},\
\text{producer SHA-256},\ \text{verifier SHA-256})
\]
together with dependency versions, arithmetic or interval backend,
platform metadata where relevant, the canonical command, expected exit
status, and deterministic generator definition.

\section{Trusted computing base}

Exact symbolic certificates rely on Python integer/rational arithmetic or on
the exact backend named in their manifests; every denominator assumption and
parameter domain is part of the corresponding certificate.  Validated
numerical certificates use outward-rounded interval endpoints, retain the
complete enclosing interval in machine-readable form, and state the
subdivision and refusal policy.  JSON parsing, the Python runtime, the
declared exact/interval kernel, and the operating system are inside the
trusted computing base unless an independent-backend check explicitly
removes one of them.

The publication release must contain an immutable archive identifier in
addition to the Git commit and file hashes.  No DOI has yet been assigned, so
this working draft does not claim that archival gate.

future-horizon regular and purely outgoing at infinity;

generalized ringdown term, or retarded convolution on

\end{itemize}
